# Echo — project context

Echo is a local-first "read YouTube instead of watching it" tool: **paste a YouTube link → get the transcript → AI digest → optionally save to a library**. Repo name is `echo` (the working dir is `yt_transcript`).

> **Continuity note:** detailed accumulated project memory is kept in a **private local store outside this repo** (not published). This file, the code, and git history are the public source of truth; when they disagree, trust the code + git history.

## Stack & how to run
- **Runtime:** Node **>=22.5** (uses the built-in `node:sqlite` — no native DB deps). ESM (`"type":"module"`).
- **Server:** `server.js` (Express, all routes). Binds `127.0.0.1:8000` by default; set `ECHO_HOST=0.0.0.0` to expose.
- **Frontend:** `public/index.html` (~680 lines of markup) + `public/app.css` + `public/app.js` + `public/theme-init.js`. Split out of the former ~9.4k-line inline monolith; still **no build step** — `app.js` is a classic script, not a module, so every top-level binding shares one scope exactly as it did inline. **The server reads and gzips all of them at boot** — restart the server to see frontend edits in dev. Brotli is served in preference to gzip when the client offers it (~17% smaller: 81.2 KB → 67.3 KB across the three files) and is compressed **in the background just after module load** — not at boot (q=11 costs ~455 ms and would more than double a 208 ms startup, on every dev restart, every Tauri sidecar launch and in CI's `boot` job) and **not on first request** (that merely moves the same cost onto the first visitor — measured 431 ms on app.js against 6 ms warm). The request path serves the buffer only `if (brotli)` and otherwise falls back to gzip, so **no request ever waits on a compressor**. `server.js` exports `brotliReady` purely so tests have a deterministic point to await; anything asserting brotli without it is racing the warm-up.
- **No inline script, no inline style, and no third-party origin.** The CSP allows no `'unsafe-inline'` at all and names no external host: `script-src 'self'; style-src 'self'; font-src 'self'`. The mode flag is served as `/echo-config.js` (`buildConfigScript`) rather than injected; **JSZip is vendored** in `public/vendor/` (from npm, hashes recorded in its README) and loaded on demand by the library export rather than blocking every page load. The only outbound origins left are YouTube's thumbnail CDNs under `img-src`.
- **AI:** goes through a provider seam (`providers.js`). Default = `ClaudeCliProvider` (shells the local `claude -p` CLI, keyless). `ApiKeyProvider` (Anthropic SDK) is used only when a per-request key is supplied (BYOK) or `ECHO_PROVIDER=api`.
- **Run:** `npm start` (local mode) · `npm test` (`node --test`) · `npm run test:page` (renders the page in a real Chrome — see "Tests miss runtime") · `ECHO_MODE=web PORT=8080 node server.js` (hosted) · `ECHO_MODE=desktop node server.js`.

## The three modes (`ECHO_MODE`)
- **local** (default): local `claude` CLI, full server-side SQLite library, no limits. The dev/personal experience — **never break this** (hard constraint).
- **desktop**: like local + **optional BYOK** (a user without the CLI can add their own Anthropic key in Settings). Used by the Tauri shell.
- **web**: **BYOK required** (key per-request via `X-Echo-Api-Key`), library is client-side IndexedDB (server library routes are `blockInWeb` 503), per-IP rate limits + payload caps. Stateless — no server secrets/volume needed.

## Where things stand
Direction: **ship to others** — a hosted web BYOK app + a free desktop app, from one codebase. UI is the **"Plaintext"** theme (2026-07-15), which replaced the dark-first "Signal" look:

- **One system monospace family** (`--font-stack`; `--font-sans`/`--font-serif`/`--font-ui`/`--font-mono` are all aliases of it). **No webfonts** — the Google Fonts `<link>` is gone, so there is no render-blocking request and no fallback flash. Don't reintroduce a webfont without re-reading the CSP-fonts gotcha.
- **Hierarchy without size.** Headings are the *same size as body text*: `--text-2xl`/`--text-3xl`/`--text-hero` all resolve to `--text-md`, and digest `h1/h2/h3` all render at `--text-xl`. Hierarchy is carried by `font-weight` + the **`--title`** token (black/white), plus a rule under `h2` and a `##` marker on `h3`. **If you need to emphasise something, reach for weight or `--title` — never font-size.**
- **Zero accent hue.** `--accent`/`--accent-dark`/`--signal`/`--signal-2` all resolve to ink, so the waveform is an ink icon rather than a brand mark. `--warn` stays chromatic **on purpose** — it is semantic, not decorative; an invisible error is a bug, not restraint.
- **No ambient background, no elevation, no decorative motion.** `body::before`/`::after` (auroras + graticule + grain) are deleted; `--shadow-*` are `none`; `--radius-*` are `0`. `body.ai-active` is still toggled but now only the text indicator reports it.
- **YouTube thumbnails are the one colour Echo doesn't author** — `.saved-card-thumb` and `.content-header-thumb` render `grayscale(1)` and return to full colour on hover.
- **No `font-style: italic` on chrome.** The system mono stack has no true italic, so it gets faked by skewing the roman and reads as broken. Authored emphasis (`#digestOutput em`) keeps it. Note: overriding italic from an *earlier* rule at equal specificity silently loses to the later one — remove it at source.
- Still fully tokenized (type / spacing / `--radius-*` / `--z-*` / `--dur-*` in `:root`); **edit via tokens, not literals** — one token change cascades to ~70 call sites.

Design review uses the `hallmark` skill (`hallmark audit <files>`); Echo passed a full audit on 2026-07-14 under the previous theme. Plaintext is grounded in a census of 41 readable sites from deadsimplesites.com (median 1–2 font families, 18/41 with no accent hue at all, ~660px measure, ~10 holding headings at body size) — see [[echo-plaintext-theme]]. Detailed session-by-session history lives in git + the private memory store; this section is the durable current-state snapshot.

**Current feature set (the core loop is `paste → transcript → digest → library`):**
- **Digest** (`digest.js`) — synthesized AI digest, the product's differentiator. Map-reduce fallback for long transcripts. Auto-tagging is folded into the digest pass (`/api/digest` runs `generateDigest` + `suggestTags` concurrently, tags best-effort with a timeout that can't reject → `suggestedTags[]`; applied at save). Digest failures (Claude CLI not installed/authed, CLI error, API auth/rate-limit) render in the shared classified error card (`renderDigestError()` → `buildErrorCard()`) with Open Settings / Try again actions, not a toast. **Streams by default** (2026-07-24) — see below.
- **Transcription** — captions by default; optional local **Whisper** (`whisper.js` + `whisperModel.js`, whisper.cpp via a vendored prebuilt `whisper-cli`, **local/desktop only**). Two modes: `fallback` (fills the no-caption dead-end) and `always` (accuracy tier). **P1+P2+P3 shipped (2026-07-19):** backend + Settings "Transcription" UI (Off/Fallback/High-accuracy + base/small model picker + on-demand download with progress), transcript source badge ("Whisper"/"YouTube captions"), library persistence (`transcriptSource`/`whisperModel`); base q5 default; **whisper-cli binary vendored** for **linux-x64** (`vendor/whisper/linux-x64/`, bundled into Tauri — turnkey, no env var) **and win32-x64** (`vendor/whisper/win32-x64/`, verified E2E 2026-07-23 under `npm start` — turnkey, no env var; not yet in a Windows Tauri bundle); macOS degrades to off (no upstream CLI). All platforms need **ffmpeg on PATH** for audio extraction. Routes `/api/transcript` + `GET /api/whisper/status` + `POST /api/whisper/model`. Transcript-fetch failures are **classified** by `classifyTranscriptFailure()` (`transcript.js`) into 7 human states — premiere / live / private / unavailable / age_restricted / geo_blocked / no_captions — and surfaced as a `renderTranscriptError()` card (headline + next-step hint + collapsible "Show technical details" holding the raw two-strike dump); the error envelope carries `reason` + `detail`. The `no_captions` case shows a Whisper-in-Settings nudge (local/desktop). See [[echo-whisper]].
- **Library** — server SQLite (`store.js`) in local/desktop; client IndexedDB in web (**two stores since v2: `videos` for full entries, `meta` for what a list row shows — written in one transaction so they cannot drift; never read `videos` to build a list**). FTS5 keyword search (`searchSummaries` cuts snippets **inside SQLite** via FTS5 `snippet()` — never hydrate entries to snippet them), tags, find-in-transcript, streamed export.
- **Accounts + library sync** (`auth.js` + `syncStore.js`, **web only, opt-in**) — Google sign-in so a library follows a visitor between devices. Off unless `ECHO_GOOGLE_CLIENT_ID` + `ECHO_GOOGLE_CLIENT_SECRET` + `ECHO_SESSION_SECRET` are all set; with any unset there is no sign-in UI, no database file and no volume. Two tables (`users`, `entries`), no passwords, no sessions table (sessions are signed cookies + a `tokenVersion` column for "sign out everywhere"), and **no API keys** — signing in does not change where the Anthropic key lives. Sync is last-write-wins by `updatedAt` with tombstones, paged at 500.
- **Local media** — `POST /api/transcript/file` runs the same Whisper stage against an uploaded audio/video file (podcast, lecture, meeting). Raw body, no upload dependency. Local files get a synthetic `file_<hash14>` id so they live in the existing library with no schema change. Local/desktop only.
- **Vault sync** — write the library into an Obsidian vault: server typed-path (`vault.js` + `/api/vault/sync`) and a client folder-picker (File System Access API, all modes). Notes filed into `YYYY-MM/` month folders + an `Echo Library.md` dashboard index note + `summary:` frontmatter. Per-note `obsidian://new` deep-link in web. See [[echo-vault-index-note]].

**Web-mode gating** (`blockInWeb` — code intact for local/desktop): the server library routes (`/api/saved*`, `/api/search`, `/api/vault/sync`) and the Whisper routes all 503/reject in web.

**Removed features — don't go looking for these** (cut as 0-use or out-of-scope): embeddings/semantic search (`@xenova/transformers`), clips, notes, favorites, saved highlights, the **Ask** feature (`/api/chat`), ask-across-library (`/api/library/ask`, `buildLibraryFtsQuery`), batch/multi-paste (`/api/batch/digest`), ccusage cost-display (`usage.js`, `/api/usage`), TTS read-aloud — and, in the **2026-07-23 lean cut**: **Discovery + channel-following + Inbox** (`discovery.js`, `/api/discovery*`, `/api/follows*`, the `follows`/`follow_seen`/`video_flags` tables), **Playlist digest** (`playlistJob.js`, `/api/playlist*`), **Cross-digest** (`/api/cross-digest`, `generateCrossDigest`), frame-augmented **"Include visuals"** digest (`frames.js`, the `includeVisuals` digest param), standalone **Share pages** (`sharepage.js`, `/s/:id`, `/api/share*`, the `shares` table), and **Verify-claims / fact-check** (`extractClaims`/`verifyClaims`, `/api/claims`, `enrich mode:'factcheck'`) plus its web-search RAG (`websearch.js`) — and, cut **2026-07-25**: **Enrich** (`/api/enrich`, the `enrich()` function in `digest.js`, the selection popover in `public/app.js`/`index.html`/`app.css`), the last of the enrich surface after Verify/fact-check went in the lean cut — zero uses across 2,558 logged events over 19 days per the local usage meter.

The extension and the plugin hold **no AI and no keys** — they are thin clients by design.

**`common/text.js` is the source of truth for `extractVideoId` + `extractSummary`.** CommonJS, because that is the only dialect all consumers reach (Node ESM imports it via `createRequire`, the plugin `require`s it, the tests load it the same way). The two surfaces that *cannot* import — the extension's classic content script and the page's inline `<script>` — keep copies, and `tests/shared-parity.test.js` runs one corpus through every implementation and fails if any disagrees. **Do not add a fifth copy; extend the parity corpus instead.**

**Accounts are built, and dormant.** `auth.js` + `syncStore.js` ship Google sign-in (OAuth + PKCE, stateless signed-cookie sessions) and library sync across devices, with unit coverage and a full-browser flow in `tests/e2e/oauth-flow.mjs`. **The sign-in flow is verified end to end (2026-07-25, 13/13).** `tests/e2e/oauth-flow.mjs` drives a real browser through a real redirect chain against a mock OIDC provider: PKCE challenge sent and verifier checked, `openid`+`email` and nothing more requested, the secret exchanged, a session established for the right account, the library synced under it, sign-out, then sign-in again landing on the *same* account with the library intact — and no page errors throughout. ## Gotchas worth knowing
- **A function copied into more than one client WILL drift, silently.** `extractSummary()` existed in three copies and all three shared the same bug for months: it broke on the first blank line after `## TL;DR`, i.e. ordinary Markdown and exactly what the model emits, so most vault notes shipped with no `summary:` frontmatter and the dashboard index lost its blurbs. No test caught it because every copy was equally wrong. Fixed by making `common/text.js` the definition and adding `tests/shared-parity.test.js`, which compares every remaining copy against it.
- **Anything that touches "the whole library" needs bounding, and a handful of test entries will never show it.** SEVEN separate bugs of this shape have now been found (sync pull paging, sync push batching, the whole-library export, search snippets, the client's IndexedDB list, the library *render*, and the FTS re-index on every save), all of which passed every test because every fixture held ten entries. Measured: the export held +102 MB of heap to emit a 42 MB payload; each search read 2.0 MB of transcript for 4 KB of snippets; the web library read 13.1 MB out of IndexedDB to render a 23 KB list; rendering 500 cards built 1.15 MB of HTML into 10,851 DOM nodes with 2,043 individually-wired listeners (2,295 ms to open, 293 ms per re-render — and a re-render fires on every tag edit and every debounced keystroke); and each save re-scanned the entire FTS index. **Seed a few hundred entries before believing a library-wide path is fine.** Note the last two are *write* and *render* paths — this pattern is not only about reads. **Re-swept 2026-07-25 at 500 and 2,000 entries** (realistic 815-segment transcripts; 55 MB and 221 MB databases) — all seven are closed and stay closed at 4× the scale: unpaged `/api/saved` 27→71 ms, search 11→16 ms (**flat**, because snippets are built inside SQLite), `POST /api/saved` 8→19 ms, and 500 seeded saves in 0.8 s, which is the FTS-reindex bug's own proof. The export streamed a **134 MB payload while RSS rose 52 MB** (buffered would need 134 MB+). Client-side, **opening the library costs the same at 2,000 entries as at 500** — 60 cards, 1,619 nodes, ~24 ms, against the 2,295 ms / 10,851 nodes on record. One limit remains and is **deliberate, not a bug**: the windowed render appends without evicting, so scrolling to the end accumulates DOM for the session (501 cards / 13,480 nodes at 500 entries; ~135k nodes extrapolated to a fully-scrolled 5,000). It costs ~4% on a re-render (330 ms collapsed vs 343 ms expanded, debounce-dominated) and self-heals — any filter drops back to a 120-card, 3,233-node window. Worth revisiting only if libraries reach thousands *and* users scroll them end to end; the fix would be virtual scrolling, which needs fixed row heights the card grid does not have.
- **`GET /api/saved` pages only when asked.** Bare `/api/saved` returns the whole metadata array exactly as it always did (the export, the vault sync and the plugin all want that); `?limit=&offset=` returns `{entries, total, hasMore}`. The client takes a 120-entry first page, paints, then walks the rest in the background — 194 ms to first cards at 500 entries against 1,065 ms — because the local filter and sort work over the *complete* list and would quietly go wrong on a partial one. `updateLibraryCount()` reads `savedTotal`, not `savedList.length`, or the count visibly climbs as pages land. Note `listEntries()` reads the whole `tags` table when unpaged and an `IN (…)` list only when paged: an IN list over a big library would hit `SQLITE_MAX_VARIABLE_NUMBER`, which is the same works-at-500-breaks-at-40k trap in a new costume.
- **The library list renders a window at a time, and its listeners are delegated.** `renderSavedList()` paints `SAVED_WINDOW_SIZE` (60) cards and extends via an `IntersectionObserver` on a `.saved-window-sentinel`; `ensureSavedDelegation()` attaches ONE listener set to `#savedOutput`, once. Two things follow. **Never re-introduce per-card `addEventListener` in the render path** — appended cards would be dead, and the cost would scale with the library again. And **a re-render preserves the window only when the entry ids are identical** (`savedWindowKey`), which is what stops a tag edit from throwing someone 300 cards deep back to the top; a filter change resets to one page on purpose. Known trade-off: the browser's own Ctrl+F only sees rendered cards, which the in-app search covers.
- **Sync moves libraries, and a library is transcripts — bound BOTH directions by size.** Pull was paged from the start; push was not, and 200 saved videos serialise to ~25 MB against a 5 MB body limit, so the first sync of any real library failed outright. The client now batches by serialised size (not entry count — entries vary hugely) and only clears its tombstones once every batch lands. An entry larger than one whole request is skipped with a warning rather than wedging every future sync behind it.
- **`store.js` opens its database on FIRST USE, not at import.** server.js imports it in every mode, but web mode `blockInWeb`s every route that touches it — eager opening created a SQLite file that could never be read, in a container that is meant to be stateless and would fail on a read-only filesystem.
- **A paged sync endpoint must not return a cursor past what it sent.** `pullEntries` truncates at 500 rows but returned `serverTime = now` regardless; the client stores that and asks for everything *after* it, so a library over 500 entries lost the remainder on a new device — silently and permanently. It now returns `hasMore` and, when truncated, the last row actually delivered; the client walks pages. Every existing sync test used a handful of entries, so the suite was green throughout.
- **`tests/tauri-bundle.test.js` only sees what its regex sees.** It walks `from './x.js'`, `import('./x.js')` and now `require('./x.js')` — the last was added when `common/text.js` arrived, because the server loads it through `createRequire` and a static-import-only walk would have let it silently miss the desktop bundle. A new *dialect* of import needs the regex extended, or the module never ships.
- **Playwright's default headless build cannot load extensions.** It is the headless *shell*; the symptom is zero service workers and no injected button, with no error. Use `channel: 'chromium'` (the full build) or `executablePath`. Cost an hour once.
- **Removing a route? Grep the frontend for indirect callers, not just the literal path.** When cutting `/api/chat`, an initial scout reported "no frontend caller" and the route was deleted — but the Ask tab called it via an `aiFetch('/api/chat', …)` wrapper, leaving a 404-on-click P0. A `vishnu-sentinel-scan` after the fact caught it. Always: after removing an endpoint, integration-scan for the endpoint string AND for wrapper helpers (`aiFetch`/`apiFetch`) before calling it done.
- **Digest CLI isolation:** the `claude -p` digest subprocess must spawn with `cwd=tmpdir()` + an isolating `--system-prompt`, or it leaks this repo's own CLAUDE.md/memory into digests.
- **Testing the CLI provider from inside Claude Code gives false results.** A `claude -p` subprocess spawned from a Claude Code session inherits `CLAUDECODE=1` + `CLAUDE_CODE_*` and behaves *differently* from the one a user's `node server.js` spawns — so a check can pass in-session and fail in production. Found 2026-07-15 chasing the auto-tag language bug: identical code/input/`language:'English'` returned English tags **with** the env set (8/8) and Indonesian tags **without** it (4/4). Three hypotheses (plumbing, nondeterminism, stale server) were wrongly cleared because the repro kept "passing". Always verify the CLI path with `env -u CLAUDECODE -u CLAUDE_CODE_ENTRYPOINT -u CLAUDE_CODE_SESSION_ID -u CLAUDE_CODE_CHILD_SESSION -u CLAUDE_CODE_GIT_BASH_PATH …`, or against a server the user started. Sibling of the isolation gotcha above, but it corrupts *verification* rather than output.
- **Prompt directives must not contradict each other.** `languageDirective()` returns "Answer in **English** using concise Markdown." — fine for `generateDigest`, but it was injected into `suggestTags`, whose next line demands "STRICT JSON … no code fences". The model resolved the contradiction by dropping the directive entirely and tagging in the source video's language. `suggestTags` now builds its own `tagLanguage` instruction with no Markdown request; a unit test guards the prompt text, since the contract-level tests can't see this and the suite never spawns the real CLI.
- **Windows `.cmd` spawns:** `spawn('*.cmd', args, {shell:false})` throws `EINVAL` synchronously on Windows (Node post-CVE-2024-27980). Use `shell:true` with a constant command string. yt-dlp is currently a real `.exe` here (unaffected); `claude` already routes via `cmd.exe /c`.
- **URL scheme filtering by host is unsafe:** `new URL('javascript:alert(1)').host === ''` (empty string), so host-based filters like `host.includes('duckduckgo.com')` pass `javascript:`/`file:`/`data:` URLs through. Always validate scheme with `/^https?:\/\//i` before using a URL. (Principle retained from the deleted `websearch.js resolveHref()`; still applies anywhere Echo consumes a URL.)
- **Tests miss runtime:** `node --test` doesn't spawn the real CLI or load the page under CSP. Before calling UI work done, drive a real digest + load the page (screenshots across light/dark/mobile). Four harnesses exist for what unit tests structurally cannot reach, none part of `npm test`: `tests/e2e/page-smoke.mjs` (`npm run test:page` — renders the page and asserts layout invariants; needs only a real Chrome, no npm dependency, since Node 22's global `WebSocket` speaks CDP directly — skips locally without Chrome, fails in CI via `ECHO_REQUIRE_BROWSER=1`), `tests/e2e/oauth-flow.mjs` (the whole sign-in flow against a mock provider, needs Playwright), `extension/test/e2e.mjs` (injection + SPA navigation), and CI's `boot` job (every module parses; the server boots in all three modes). The page smoke test exists because **two layout regressions shipped past a fully green 427-test suite** and were caught by a human saying the page "looked kind of broken"; it now also guards the `[hidden]` trap below. Assertions there are **mutation-tested** — reverting a fix must make it fail, or it is proving nothing.
- **A class that sets `display` silently defeats `[hidden]`.** Author rules beat the UA `[hidden] { display: none }`, so `el.hidden = true` on anything styled `display: flex/inline-flex/block` does *nothing*. Every such element needs an explicit `X[hidden] { display: none }` guard, or the `display:none`-by-default + `:not([hidden])` idiom — the codebase uses both, in a dozen places. Two real bugs from this in one day: `.local-file-row` was **always** visible, including in web mode where its route is `blockInWeb` and on machines with no Whisper (defeating the "don't offer a picker that dead-ends in *download a model first*" logic), and `#digestExportRow` showed Copy / Download / Print with nothing to export the moment the Digest tab was opened. A browser probe of all 28 hideable elements found no others. **When adding an element you intend to hide, add the guard in the same commit** — nothing else catches it.
- **The top chrome is a group, and a new sibling silently falls out of it.** `.site-header`, `.command-bar`, `.local-file-row`, `#status` and `.next-action-nudge` share one rule pinning them to `--chrome-max` and centring them. Anything added between the header and the status line that is *not* added to that list stretches to `--col-max` instead and hangs `(1000 − 760) / 2 = 120px` outside the reading column. That is exactly what `.local-file-row` did from the day it was added. Related: the row sits **flush with the column edge on purpose** — indenting it to meet the URL text *inside* the field was tried and rejected, because it breaks the one straight left edge the column holds.
- **Natural-language → FTS5 query:** raw questions passed to SQLite MATCH operator AND all tokens, so questions with stopwords return zero rows — if a future feature needs NL-question retrieval over the FTS5 store, strip stopwords and OR-join quoted tokens (e.g., "what is machine learning" → `("machine" OR "learning")` in MATCH syntax) rather than passing the raw question. (Previously lived in `store.js` as `buildLibraryFtsQuery()`, removed with the C1 ask-across-library feature cut.)
- **Test video:** use `youtube.com/watch?v=GRzaq5AHiV8` for manual/E2E checks.
- **Tauri bundle drift:** `tauri.conf.json` `bundle.resources` lists backend `.js` files individually — a new backend module (or a new `./x.js` import) that isn't added there crashes the desktop sidecar at runtime with `ERR_MODULE_NOT_FOUND`, and `node --test` / the `.deb`/`.rpm` bundlers never catch it (they don't start the backend). `tests/tauri-bundle.test.js` guards this. Conversely, when you **delete** a backend module, remove it from `bundle.resources` too (done for the 5 lean-cut modules). AppImage bundling also needs a production-only `node_modules` + `NO_STRIP=1` + `APPIMAGE_EXTRACT_AND_RUN=1`, all handled by `npm run tauri:build` (see [`DESKTOP.md`](DESKTOP.md)).
- **Vendoring CommonJS into ESM:** importing a bare CommonJS third-party file (e.g., `module.exports`) into this ESM repo (`"type":"module"`) silently yields an empty namespace — `analyzeText()` becomes `undefined` with no error. Fix: create a scoped `package.json` in the vendor dir with `{"type":"commonjs"}` so files load as CJS, then import via `createRequire`. Don't touch the root `package.json` type. See `tools/ai-tell/` and [[echo-digest-ai-tell-eval]].
- **Self-contained CSP pages cannot load external fonts:** referencing web-font family names (e.g. 'Space Grotesk', 'Inter', 'JetBrains Mono') without an inline `@font-face` silently falls back to system fonts and looks generic. Use deliberate system font stacks (e.g. `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`). (Applies to any server-rendered/standalone HTML; the former offender `sharepage.js` was removed in the lean cut.)
- **File System Access API is Chromium-only + gated:** `window.showDirectoryPicker()` (used by web vault folder-sync) exists only in Chromium (Chrome/Edge, **not** Firefox/Safari), needs a **secure context** (https or localhost) and a **user gesture** (call it from a click handler — `requestPermission` also needs the gesture, so chain it off the same click). `FileSystemDirectoryHandle`s are **not** serializable to localStorage — persist them in **IndexedDB**. Always feature-detect (`'showDirectoryPicker' in window`) and fall back (Echo falls back to the ZIP export). Headless browsers usually lack the API, so a real E2E folder-write can't be automated — verify everything up to the native picker.
- **`obsidian://new` URI length ceiling:** deep-linking a note into Obsidian via `window.location.href = 'obsidian://new?…&content=…'` fails silently past the OS protocol-handler limit (well under a full transcript on Windows). Send **digest-only** markdown and guard the final URI length (Echo declines >8000 chars, pointing the user to folder-sync/ZIP). Custom-scheme navigation is **not** blocked by this app's CSP — `default-src` doesn't govern navigation and there's no `navigate-to`/`form-action` directive.
- **Inline `<script>`, inline `<style>`, `style=""` attributes AND inline event handlers (`onerror=`, `onclick=`, …) are all blocked now, and all fail SILENTLY** — in a browser only; `node --test` cannot see any of them. Put new code in `public/app.js` and new CSS in `public/app.css`, and reach for a class rather than a style attribute. The distinction that matters when styling dynamically: **`el.style.width = x` is the CSSOM and is fine**; a `style=""` inside an `innerHTML` string is parsed markup and is refused. `showTranscriptSkeleton()` builds nodes and assigns `.style.width` for exactly this reason. `tests/page-serving.test.js` asserts the policy, that no `<style>`/inline `<script>` survives, and that neither the HTML nor `app.js` contains a `style=` **or an `on*=` attribute**. The handler case is the one that actually bit: **two** thumbnail fallbacks (`.saved-card-thumb` and `#contentHeaderThumb`) used `onerror="this.remove()"` and had quietly never run since the CSP was tightened — a broken thumbnail just sat there as a broken-image box. Both are now real listeners; note `error` does **not bubble**, so the delegated one on `#savedOutput` must be registered with `capture: true`. Also expect `loading="lazy"` images to fire `error` only once scrolled into view, so a "half of them weren't removed" reading is usually lazy loading, not a broken fallback.
- **The digest streams, and every layer of that has a fallback to the way it worked before.** `POST /api/digest?stream=1` opens an SSE response with four event types: `phase` (map-reduce progress, before any digest text exists), `token`, `done` (the *identical* payload the JSON route returns), and `error`. **Without `?stream=1` the route still answers with plain JSON** — the Obsidian plugin and anything else built against it must not start receiving an event stream. Layers: `runClaudeStream()` (`--output-format stream-json --include-partial-messages --verbose`, NDJSON parsed with line reassembly across chunk boundaries) and `ApiKeyProvider.stream()` (SDK `messages.stream()`); `callProviderStreaming()` falls back to the buffered call when there is no `onToken` or the provider has no `stream` method; the client's `streamDigest()` returns `null` on any transport failure and `runDigest()` then re-runs it buffered. Four things to know. **An SSE response is a 200 the moment it opens**, so a mid-stream failure arrives as an `error` *event*, not a status — that is why the route builds the error envelope by hand instead of calling `sendError`. **Only the reduce phase streams** in map-reduce; the map phase produces text nobody sees, so it reports `phase` progress instead. **The final render replaces the streamed one** from the `done` payload, so the authoritative text wins and half-built Markdown settles. And **tokens are painted on a `requestAnimationFrame`**, not per token — re-rendering Markdown per token jitters and wastes work. Guarded by `tests/digest-stream.test.js`, which puts a fake `claude` on `PATH` emitting the real event shape in deliberately awkward 7-byte writes.
- **`triggerSearch()` used to short-circuit in web mode, so `IndexedDbLibrary.searchLibrary()` was unreachable** — web-mode search matched titles and tags only and could not see a word of a transcript or digest, while the same search in local mode went through FTS5 over everything. Now both modes call the adapter. Web mode paints the synchronous local filter first and lets the full-text result replace it (~0.5 s over 400 entries), and **both modes guard with `savedSearchSeq`** so a slower older query cannot overwrite a newer one. If web search ever needs to get faster, the answer is an inverted index in IndexedDB, not micro-optimising the scan — the cost is reading 400 × ~45 KB of transcript, not the string work.
- **The FTS index is keyed by `videos.rowid`, not by `videoId`.** `videoId` is an `UNINDEXED` column in `videos_fts`, so `DELETE … WHERE videoId = ?` plans as `SCAN videos_fts VIRTUAL TABLE` — a linear pass over every stored transcript on **every save**. `syncFts()` and `deleteEntry()` both delete by rowid instead; `deleteEntry` must read the rowid **before** removing the videos row. Reusing `videos.rowid` is only safe because both rows are always deleted together — leave an FTS row behind and the next video to claim that recycled rowid inherits its text. Pre-existing databases had divergent rowids (the ordinary save-then-digest flow re-inserted the FTS row and handed it a new one — measured: 40 of 40 rows), so `migrateFtsRowids()` rebuilds the index once, gated on `PRAGMA user_version`. **A future FTS schema change needs that version bumped**, or old rows silently survive. Guarded by `tests/store-fts-rowid.test.js`.
- **Write control characters as `\uXXXX` escapes, never as raw bytes.** `renderMarkdown()` parks inline code spans behind a U+0000 sentinel; it used to hold a literal NUL, which made `public/app.js` read as a **binary file** to grep, git and every diff viewer, so the largest file in the repo silently dropped out of content searches. `esc()` now also strips control characters from input, so a digest carrying that byte cannot forge a placeholder (not injection — the text is escaped first — but it steals a `<code>` element or renders the literal string "undefined"). `tests/markdown-render.test.js` fails on any raw control character in `app.js`.
- **A theme change in `public/index.html` does NOT reach the brand assets.** The token cascade stops at that file. Three other places carry the palette independently and must be updated by hand, or the app silently keeps half the old identity: (1) **`public/favicon.svg`** — an SVG favicon cannot read the page's custom properties, so it needs its own `@media (prefers-color-scheme)` and its own literals; **bump the `?v=` on the `<link rel="icon">` or Firefox will serve the old mark forever**. (2) **`public/echo-logo.svg`** — same, plus it can't load a webfont (it asked for 'Space Grotesk' for months and silently fell back). (3) **`src-tauri/icons/*`** — binaries; regenerate with `npx tauri icon <1024px.png>`, then **delete the `android/` and `ios/` dirs it creates** (Echo is desktop-only and `tauri.conf.json` lists neither). The desktop icon is the one surface that can't be theme-aware — a static `.ico` on an unknown-colour taskbar — so it carries its own paper ground rather than inheriting. (The former 4th offender, `sharepage.js`'s own `:root` block, was removed in the lean cut.)
- **Classify transcript failures — never dump the raw two-strike error at the user.** When both fetch paths (youtube-transcript + yt-dlp) fail, the code used to concatenate `Primary: … Fallback (yt-dlp): …` straight into the status line, burying the one useful fact (e.g. `Premieres in 7 days`) at the tail of a `Command failed: yt-dlp …` dump. `classifyTranscriptFailure()` (`transcript.js`) now parses the yt-dlp stderr + primary error into a `reason` (premiere/live/private/unavailable/age_restricted/geo_blocked/no_captions) with a human `message` + `hint`; the raw dump is preserved as `error.detail` behind the card's "Show technical details" disclosure. **`no_captions` is the catch-all default** — any *novel* failure string that matches no pattern reads as "No transcript available," so when adding a newly-detectable case put its regex *before* the default and add a case to `tests/transcript-error-classify.test.js`. Both AI-ish failure surfaces now share ONE card component: `buildErrorCard({headline, hint, detail})` + the `.error-card*` CSS (renamed from `.transcript-error*`). `renderTranscriptError()` renders `/api/transcript` failures into `#output` (with the no_captions Whisper nudge); `renderDigestError()` renders `/api/digest` failures into `#digestOutput` with code-driven action buttons — **Open Settings** for key/CLI-auth issues (incl. the desktop BYOK-missing override) and **Try again** (re-runs `runDigest`) for rate-limits/transient failures. `CLAUDE_FAILED` (digest.js) + `API_FAILED` (providers.js) carry `error.detail` so the disclosure has content. Render via these, not a toast/`setStatus`; `handleApiError()` (toast) remains only for the library flows.
- **yt-dlp silently degrades without a JS runtime:** yt-dlp 2026.06.09+ falls back to a degraded extraction client when no JavaScript runtime is available, then *silently* omits formats — no error is raised, but format listings become incomplete. The symptom is missing formats in metadata, not a visible crash. Echo requires Node >=22.5 and passes `--js-runtimes node` on **all four** of its `yt-dlp` spawns — two in `transcript.js` (caption fetch, metadata) and two in `whisper.js` (audio probe, audio download); the lean cut removed the `discovery.js`/`frames.js` ones, not whisper's. Controlled by `ECHO_YTDLP_JS_RUNTIME` (default `'node'`). To disable (e.g., for an older yt-dlp that predates the flag), set `ECHO_YTDLP_JS_RUNTIME=` (empty string) to omit the flag.
