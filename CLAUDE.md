# Echo — project context

Echo is a local-first "read YouTube instead of watching it" tool: **paste a YouTube link → get the transcript → AI digest → optionally save to a library**. Repo name is `echo` (the working dir is `yt_transcript`).

> **Continuity note:** detailed accumulated project memory is kept in a **private local store outside this repo** (not published). This file, the code, and git history are the public source of truth; when they disagree, trust the code + git history.

## Stack & how to run
- **Runtime:** Node **>=22.12** (Astro 7.2 engine requirement; also uses the built-in `node:sqlite` — no native DB deps). ESM (`"type":"module"`).
- **Server:** `server.js` (Express, all routes). Binds `127.0.0.1:8000` by default; set `ECHO_HOST=0.0.0.0` to expose.
- **Frontend:** Astro 7.2 (`output: 'static'`, no server-side rendering). Sources under `src/`: `pages/index.astro` (the page), `layouts/BaseLayout.astro`, 15 components in `components/`, `client/main.js` (ES module, 224 KB), `styles/app.css` (99 KB). Build outputs to `dist/` with content-hashed bundles in `dist/_astro/` (entry chunk 82.5 KB minified, stylesheet 51 KB minified). **The server reads and gzips everything at boot and refuses to start if `dist/` is missing** (`npm run build` first) — restart the server to see frontend edits in dev. `main.js` is still ONE module with one top-level scope (the migration deliberately did not decompose it; verified to behave identically under module semantics). Brotli is served in preference to gzip when the client offers it and is compressed **in the background just after module load** — not at boot.
- **No inline script, no inline style, and no third-party origin.** The CSP allows no `'unsafe-inline'` at all and names no external host: `script-src 'self'; style-src 'self'; font-src 'self'`. Kept true under the bundler via `inlineStylesheets: 'never'` + `devToolbar.enabled: false` in `astro.config.mjs`. The mode flag is served as `/echo-config.js` (`buildConfigScript`) rather than injected; **JSZip is vendored** in `public/vendor/` (copied verbatim to `dist/vendor/`) (from npm, hashes recorded in its README) and loaded on demand by the library export rather than blocking every page load. The only outbound origins left are YouTube's thumbnail CDNs under `img-src`.
- **AI:** goes through a provider seam (`providers.js`), which since 2026-09-11 is a **registry of per-provider facts** — context window, output ceiling, chars-per-token, whether a key is needed, and which reasoning dialect it speaks. Three providers implement one `{ call, stream }` interface: `claude-cli` (default; shells the local `claude -p`, keyless), `anthropic` (SDK, BYOK), `deepseek` (OpenAI-compatible over plain `fetch` — no new dependency). `ECHO_PROVIDER` takes `cli`/`api`/`anthropic`/`deepseek`; a provider can also be named **per request** via `X-Echo-Provider`, which is what the in-app picker sends. `GET /api/providers` serves the registry and the browser builds its pickers from that response rather than holding a copy of it. Keys are stored **one per provider**. Those facts must not be shared between providers, and getting them wrong is silent — see [`PROVIDERS.md`](PROVIDERS.md) and the truncation gotcha below.
- **Run:** `npm start` (build then boot) · `npm run build` (Astro static build to `dist/`) · `npm run serve` (boot without building) · `npm run dev` (Astro HMR on :4321, proxying `/api` and `/echo-config.js` to :8000) · `npm test` (build then run suite with `node --test`) · `npm run test:only` (suite without the build) · `npm run test:page` (real Chrome — see "Tests miss runtime") · `npm run serve:public` (Holesail + Janus tunnel).

## The three modes (`ECHO_MODE`)
- **local** (default): local `claude` CLI, full server-side SQLite library, no limits. The dev/personal experience — **never break this** (hard constraint).
- **desktop**: like local + **optional BYOK** (a user without the CLI can add a key for whichever provider they pick — Anthropic or DeepSeek — in Settings). Used by the Tauri shell.
- **web**: **BYOK required** (key per-request via `X-Echo-Api-Key` + `X-Echo-Provider`, for whichever provider the registry offers), library is client-side IndexedDB (server library routes are `blockInWeb` 503), per-IP rate limits + payload caps. Stateless — no server secrets/volume needed.

## Where things stand
Direction: **ship to others** — a hosted web BYOK app + a free desktop app, from one codebase. UI is the **"Plaintext"** theme (2026-07-15), which replaced the dark-first "Signal" look:

- **One system monospace family** (`--font-stack`; `--font-sans`/`--font-serif`/`--font-ui`/`--font-mono` are all aliases of it). **No webfonts** — the Google Fonts `<link>` is gone, so there is no render-blocking request and no fallback flash. Don't reintroduce a webfont without re-reading the CSP-fonts gotcha.
- **Hierarchy without size.** Headings are the *same size as body text*: `--text-2xl`/`--text-3xl`/`--text-hero` all resolve to `--text-md`, and digest `h1/h2/h3` all render at `--text-xl`. Hierarchy is carried by `font-weight` + the **`--title`** token (black/white), plus a rule under `h2` and a `##` marker on `h3`. **If you need to emphasise something, reach for weight or `--title` — never font-size.**
- **Zero accent hue.** `--accent`/`--accent-dark`/`--signal`/`--signal-2` all resolve to ink, so the waveform is an ink icon rather than a brand mark. `--warn` stays chromatic **on purpose** — it is semantic, not decorative; an invisible error is a bug, not restraint.
- **No ambient background, no elevation, no decorative motion.** `body::before`/`::after` (auroras + graticule + grain) are deleted; `--shadow-*` are `none`; `--radius-*` are `0`. `body.ai-active` is still toggled but now only the text indicator reports it.
- **YouTube thumbnails are the one colour Echo doesn't author** — `.saved-card-thumb` and `.content-header-thumb` render `grayscale(1)` and return to full colour on hover.
- **No `font-style: italic` on chrome.** The system mono stack has no true italic, so it gets faked by skewing the roman and reads as broken. Authored emphasis (`#digestOutput em`) keeps it. Note: overriding italic from an *earlier* rule at equal specificity silently loses to the later one — remove it at source.
- Still fully tokenized (type / spacing / `--radius-*` / `--z-*` / `--dur-*` in `:root`); **edit via tokens, not literals** — one token change cascades to ~70 call sites.

Design review uses the `hallmark` skill (`hallmark audit <files>`); Echo passed a full audit on 2026-07-14 under the previous theme. Plaintext is grounded in a census of 41 readable sites from deadsimplesites.com (median 1–2 font families, 18/41 with no accent hue at all, ~660px measure, ~10 holding headings at body size) — see [[echo-plaintext-theme]]. Detailed session-by-session history lives in git + the private memory store; this section is the durable current-state snapshot.

**Current feature set (the core loop is `paste → transcript → digest → library`):**
- **Digest** (`digest.js`) — synthesized AI digest, the product's differentiator. Map-reduce fallback for long transcripts, at a threshold **derived from the provider's context window** rather than a constant (a 1M-token provider stops chunking where Claude would start). **Which provider writes it is a per-run choice** (2026-09-11): the picker in Options/Settings switches between the local CLI, the Anthropic API and DeepSeek — one key per provider — with a reasoning level that is off by default and translated into each provider's own dialect. See [`PROVIDERS.md`](PROVIDERS.md). Auto-tagging is folded into the digest pass (`/api/digest` runs `generateDigest` + `suggestTags` concurrently, tags best-effort with a timeout that can't reject → `suggestedTags[]`; applied at save). Digest failures (Claude CLI not installed/authed, CLI error, API auth/rate-limit) render in the shared classified error card (`renderDigestError()` → `buildErrorCard()`) with Open Settings / Try again actions, not a toast. **Streams by default** (2026-07-24) — see below.
- **Transcription** — captions by default; optional local **Whisper** (`whisper.js` + `whisperModel.js`, whisper.cpp via a vendored prebuilt `whisper-cli`, **local/desktop only**). Two modes: `fallback` (fills the no-caption dead-end) and `always` (accuracy tier). **P1+P2+P3 shipped (2026-07-19):** backend + Settings "Transcription" UI (Off/Fallback/High-accuracy + base/small model picker + on-demand download with progress), transcript source badge ("Whisper"/"YouTube captions"), library persistence (`transcriptSource`/`whisperModel`); base q5 default; **whisper-cli binary vendored** for **linux-x64** (`vendor/whisper/linux-x64/`, bundled into Tauri — turnkey, no env var) **and win32-x64** (`vendor/whisper/win32-x64/`, verified E2E 2026-07-23 under `npm start` — turnkey, no env var; not yet in a Windows Tauri bundle); macOS degrades to off (no upstream CLI). All platforms need **ffmpeg on PATH** for audio extraction. Routes `/api/transcript` + `GET /api/whisper/status` + `POST /api/whisper/model`. Transcript-fetch failures are **classified** by `classifyTranscriptFailure()` (`transcript.js`) into 8 human states — bot_block / premiere / live / private / unavailable / age_restricted / geo_blocked / no_captions — and surfaced as a `renderTranscriptError()` card (headline + next-step hint + collapsible "Show technical details" holding the raw two-strike dump); the error envelope carries `reason` + `detail`. The `no_captions` case shows a Whisper-in-Settings nudge (local/desktop). See [[echo-whisper]].
- **Library** — server SQLite (`store.js`) in local/desktop; client IndexedDB in web (**two stores since v2: `videos` for full entries, `meta` for what a list row shows — written in one transaction so they cannot drift; never read `videos` to build a list**). FTS5 keyword search (`searchSummaries` cuts snippets **inside SQLite** via FTS5 `snippet()` — never hydrate entries to snippet them), tags, find-in-transcript, streamed export.
- **Accounts + library sync** (`auth.js` + `syncStore.js`, **web only, opt-in**) — Google sign-in so a library follows a visitor between devices. Off unless `ECHO_GOOGLE_CLIENT_ID` + `ECHO_GOOGLE_CLIENT_SECRET` + `ECHO_SESSION_SECRET` are all set; with any unset there is no sign-in UI, no database file and no volume. Two tables (`users`, `entries`), no passwords, no sessions table (sessions are signed cookies + a `tokenVersion` column for "sign out everywhere"), and **no API keys** — signing in does not change where the Anthropic key lives. Sync is last-write-wins by `updatedAt` with tombstones, paged at 500.
- **Local media** — `POST /api/transcript/file` runs the same Whisper stage against an uploaded audio/video file (podcast, lecture, meeting). Raw body, no upload dependency. Local files get a synthetic `file_<hash14>` id so they live in the existing library with no schema change. Local/desktop only.
- **Vault sync** — write the library into an Obsidian vault: server typed-path (`vault.js` + `/api/vault/sync`) and a client folder-picker (File System Access API, all modes). Notes filed into `YYYY-MM/` month folders + an `Echo Library.md` dashboard index note + `summary:` frontmatter. Per-note `obsidian://new` deep-link in web. See [[echo-vault-index-note]].

**Web-mode gating** (`blockInWeb` — code intact for local/desktop): the server library routes (`/api/saved*`, `/api/search`, `/api/vault/sync`) and the Whisper routes all 503/reject in web.

**Removed features — don't go looking for these** (cut as 0-use or out-of-scope): embeddings/semantic search (`@xenova/transformers`), clips, notes, favorites (the dead `favorite` plumbing was finally removed from `store.js`/`main.js`/`pds.js` on 2026-08-19 — the **SQLite column stays**, since existing databases carry it and an `ALTER TABLE DROP COLUMN` is more risk than two dead bytes), saved highlights, the **Ask** feature (`/api/chat`), ask-across-library (`/api/library/ask`, `buildLibraryFtsQuery`), batch/multi-paste (`/api/batch/digest`), ccusage cost-display (`usage.js`, `/api/usage`), TTS read-aloud — and, in the **2026-07-23 lean cut**: **Discovery + channel-following + Inbox** (`discovery.js`, `/api/discovery*`, `/api/follows*`, the `follows`/`follow_seen`/`video_flags` tables), **Playlist digest** (`playlistJob.js`, `/api/playlist*`), **Cross-digest** (`/api/cross-digest`, `generateCrossDigest`), frame-augmented **"Include visuals"** digest (`frames.js`, the `includeVisuals` digest param), standalone **Share pages** (`sharepage.js`, `/s/:id`, `/api/share*`, the `shares` table), and **Verify-claims / fact-check** (`extractClaims`/`verifyClaims`, `/api/claims`, `enrich mode:'factcheck'`) plus its web-search RAG (`websearch.js`) — and, cut **2026-07-25**: **Enrich** (`/api/enrich`, the `enrich()` function in `digest.js`, the selection popover in what is now `src/client/main.js`/`src/pages/index.astro`/`src/styles/app.css`), the last of the enrich surface after Verify/fact-check went in the lean cut — zero uses across 2,558 logged events over 19 days per the local usage meter.

**Module map:** `server.js` (all Express routes) · `providers.js` (provider **registry**: per-provider limits + reasoning dialect, truncation detection, `publicProviderList()`, per-provider key validation) · `transcript.js` (yt-dlp/caption fetch + `classifyTranscriptFailure` error states) · `whisper.js` (local whisper.cpp STT + `transcribeFile` for local media) · `whisperModel.js` (model registry + download/cache) · `digest.js` · `store.js` (SQLite, local/desktop — **one database file per owner**; `forOwner(id)` scopes the API, the bare exports are the single-user default library at the original path) · `auth.js` (Google sign-in + stateless signed-cookie sessions) · `atproto.js` (Bluesky sign-in via app passwords) · `pds.js` (atproto record/blob transport) · `pdsSync.js` (mirror policy: tokens, ordering, failure handling) · `syncStore.js` (accounts, approvals, sealed Bluesky tokens) · `common/text.js` (**shared with every client**, see below) · `markdown.js` (export + `buildVaultIndex`) · `vault.js` · `sanitize.js` · `usagelog.js` + `usage_stats.mjs` (local JSONL action meter) · `tools/holesail-serve.mjs` (public tunnel via Holesail + Janus) · `tools/ai-tell/` (AI-writing eval, `npm run digest:aitell`) · `tools/fidelity/` (digest-fidelity eval, `npm run digest:fidelity`) · `tools/ab-compare.mjs` (provider A/B eval, `npm run digest:ab`) · `tools/vendor-whisper-backends.mjs`.

**Four clients, one backend.** `src/pages/index.astro` (the web app, built to `dist/`), `extension/` (Chrome MV3 only — fetches transcripts on the visitor's tab using their IP and session, passes them to Echo in the URL fragment as `#echo-tx=<gzip+base64url>`), `obsidian-plugin/` (a note per video, talking to a running Echo over HTTP), and the server itself. The extension and the plugin hold **no AI and no keys** — they are thin clients by design. **The extension does not run in Firefox** (which requires `background.scripts`, not `background.service_worker`).

**`common/text.js` is the source of truth for `extractVideoId` + `extractSummary`.** CommonJS, because that is the only dialect all consumers reach (Node ESM imports it via `createRequire`, the plugin `require`s it, the tests load it the same way). The two surfaces that *cannot* import — the extension's classic content script and `src/client/main.js` — keep copies, and `tests/shared-parity.test.js` runs one corpus through every implementation and fails if any disagrees. **Do not add a fifth copy; extend the parity corpus instead.**

**Bluesky accounts are built and LIVE (2026-08-13).** An instance can now be opened to other people: sign in with a Bluesky handle + app password (`atproto.js`), ask for access, an admin approves, and only then do the AI/fetch/library routes work. See [`ATPROTO.md`](ATPROTO.md) for the five phases and [`ADMIN.md`](ADMIN.md) for running it. The shape:

- **Config-gated, not mode-gated.** Unset `ECHO_ATPROTO_ENABLED` — the default — and none of it exists: no sign-in, no gate, no database file, no behaviour change. The whole unit suite runs in exactly that state, which is the proof.
- **The gate itself is tested with the feature ON** (`tests/atproto-gating.test.js`, 27 tests, added 2026-08-19). The suite running with atproto *off* proves the feature is config-gated; it proves nothing about whether the gate refuses anyone. That file boots a child server with `ECHO_ATPROTO_ENABLED=1` and drives it over real HTTP, asserting all five refusal states across the digest/transcript/saved/search families, plus a forged-cookie case, a stale-`tokenVersion` case, and a regression guard that the gate still no-ops when disabled. Sessions are minted with the real `signToken()` from `auth.js`, not faked. **The assertions are mutation-verified**: stripping one `requireApproved` fails exactly 6 of them.
- **App passwords, not atproto OAuth.** OAuth's `client_id` is a public https URL that becomes part of every session, and this instance moves from a Holesail tunnel to a P2P host later; an origin change would sign everyone out permanently. A real Bluesky password is refused before anything is sent anywhere.
- **`requireApproved` guards all 19 routes that spend something**, and blocks anonymous visitors too — "signed out" is the state every stranger arrives in. Refusals carry a `reason` (`signed_out`/`unsubmitted`/`pending`/`rejected`) so the client shows one of five gate screens rather than one generic error.
- **Quotas are per ACCOUNT, not per IP** (`userLimit`), because the Claude quota and the residential IP are spent per person. `ECHO_ADMIN_DIDS` is an env var, so becoming an admin needs access to the machine.
- **One library FILE per account** (`store.js` `forOwner(id)`), so isolation is structural rather than a WHERE clause anyone has to remember. The bare exports are the single-user default library at the original path.
- **The PDS mirror is off by default and opt-in per account** — see the gotcha below; it publishes.

**Google accounts are built, and dormant.** `auth.js` + `syncStore.js` ship Google sign-in (OAuth + PKCE, stateless signed-cookie sessions) and library sync across devices, with unit coverage and a full-browser flow in `tests/e2e/oauth-flow.mjs`. It is **off unless three env vars are set** — `ECHO_GOOGLE_CLIENT_ID`, `ECHO_GOOGLE_CLIENT_SECRET`, `ECHO_SESSION_SECRET` — and config-gated, not mode-gated. It is the one feature that needs a **persistent volume** (`ECHO_SYNC_DB_PATH`), which is why `DEPLOY.md` has a section reconciling it with the otherwise no-volume hosting story. Note the payoff only exists on a hosted instance: in local/desktop the library already lives on the same machine, so there is nobody to sync with.

**The sign-in flow is verified end to end (2026-07-25, 13/13).** `tests/e2e/oauth-flow.mjs` drives a real browser through a real redirect chain against a mock OIDC provider: PKCE challenge sent and verifier checked, `openid`+`email` and nothing more requested, the secret exchanged, a session established for the right account, the library synced under it, sign-out, then sign-in again landing on the *same* account with the library intact — and no page errors throughout. Re-run it with `npm i --no-save playwright` (it deliberately is not a dependency; `--no-save` leaves both manifests untouched) then `ECHO_CHROMIUM=/usr/bin/google-chrome-stable node tests/e2e/oauth-flow.mjs`, which reuses a system Chrome instead of downloading one. Unconfigured — the default everywhere today — it degrades cleanly rather than half-working: `/api/auth/me` returns `{enabled:false,user:null}` at 200, `/api/auth/google` and `/api/sync/*` 503 with a hint naming the three env vars. **What none of this proves is Google's own configuration**: the redirect-URI allow-list and the consent screen live in Cloud Console and need a real client ID against real Google. Everything on Echo's side of that boundary is covered; the remaining risk is console config, not code.

A hosted instance serving arbitrary visitors would need a proxy with residential IPs, which is not built.

## Gotchas worth knowing
- **atproto repositories are PUBLIC — mirroring a library publishes it.** Verified directly against bsky.social with no credentials: `listRecords` returns 200 with records, and `getBlob` returns 200 with bytes using a CID lifted straight out of the public record (blob *enumeration* needs auth, which protects nothing, because the CID is in the record). So the PDS mirror is not a backup — it publishes titles, tags, digests and full transcripts as a reading history under a real handle, and a later delete removes your copy and not the ones that crossed the firehose on write. Hence: `ECHO_PDS_SYNC` off by default, a per-account opt-in on top, `acknowledged: true` required at the API so the server does not trust the UI to have asked, and **`file_*` local-media entries never mirrored at all, with no override** (they are lectures, meetings and voice notes). An app password is consent for Echo to act on an account; it is not consent to publish.
- **A passing assertion can be right for the wrong reason, which is worse than a failing one.** The probe asserting "nothing was written to the real repository" passed — because `getAtprotoTokens` was never imported into server.js, so the mirror threw a `ReferenceError` on every save and had never worked since being wired. The intended guarantee (the per-account opt-in) was not what produced the result. Re-run the guarantee with the *other* protections deliberately disabled, so the thing under test is the only thing that can produce the pass. Sibling: the mirror is fire-and-forget by design, so its failures reach only a `console.warn` — **a broken mirror looks exactly like a disabled one.**
- **`app.set('trust proxy')` was web-mode only, and `serve:public` fronts a LOCAL instance.** Behind Holesail + Janus every request arrives from the tunnel, so `req.ip` — which every rate limiter keys on — was identical for everyone. Measured: twelve sign-in attempts from twelve visitors, ten allowed then two 429s. One shared bucket, so one person fumbling their app password locked out sign-in for everybody. Now `ECHO_TRUST_PROXY`, set by `serve:public` because that script is what put the proxy there. **Do not default it on** — trusting `X-Forwarded-For` with nothing in front lets any client claim any address and walk past the limiter. Also: measuring this needs a request that fails LOCALLY (a malformed handle), because a real handle's 429 comes from Bluesky's own per-account `createSession` limit and is indistinguishable from ours.
- **A migration that returns early on one column silently skips every column added later.** `migrateUsersForApproval` checked for `status` and then added its whole list, so once `status` existed nothing new was ever added — and a database created between two releases had `status` but no `last_seen`, making every query naming it fail. It was not hypothetical: this instance's own `data/echo-sync.db` was in exactly that state. Migrate **per column**, and fire a backfill only on the pass that adds the column it belongs to (re-running the grandfather UPDATE later would silently approve the entire pending queue).
- **A dead control is a worse first impression than an absent one.** The gated landing page rendered the full marketing hero plus an enabled "Paste a YouTube link" box that did nothing, with the sign-in below it as a small link inside an *error card*. The fix was not better copy: the gate state IS the page's state, derived from `/api/auth/me` (`applyGateState`), so one of five screens shows and controls that cannot work are not rendered. Deriving the screen from state rather than from the last error also made a whole class of bug unrepresentable — the previous version painted a card from an error handler and nothing repainted it, so after signing in the page still said "Sign in to use this Echo".
- **A function copied into more than one client WILL drift, silently.** `extractSummary()` existed in three copies and all three shared the same bug for months: it broke on the first blank line after `## TL;DR`, i.e. ordinary Markdown and exactly what the model emits, so most vault notes shipped with no `summary:` frontmatter and the dashboard index lost its blurbs. No test caught it because every copy was equally wrong. Fixed by making `common/text.js` the definition and adding `tests/shared-parity.test.js`, which compares every remaining copy against it.
- **Anything that touches "the whole library" needs bounding, and a handful of test entries will never show it.** SEVEN separate bugs of this shape have now been found (sync pull paging, sync push batching, the whole-library export, search snippets, the client's IndexedDB list, the library *render*, and the FTS re-index on every save), all of which passed every test because every fixture held ten entries. Measured: the export held +102 MB of heap to emit a 42 MB payload; each search read 2.0 MB of transcript for 4 KB of snippets; the web library read 13.1 MB out of IndexedDB to render a 23 KB list; rendering 500 cards built 1.15 MB of HTML into 10,851 DOM nodes with 2,043 individually-wired listeners (2,295 ms to open, 293 ms per re-render — and a re-render fires on every tag edit and every debounced keystroke); and each save re-scanned the entire FTS index. **Seed a few hundred entries before believing a library-wide path is fine.** Note the last two are *write* and *render* paths — this pattern is not only about reads. **Re-swept 2026-07-25 at 500 and 2,000 entries** (realistic 815-segment transcripts; 55 MB and 221 MB databases) — all seven are closed and stay closed at 4× the scale: unpaged `/api/saved` 27→71 ms, search 11→16 ms (**flat**, because snippets are built inside SQLite), `POST /api/saved` 8→19 ms, and 500 seeded saves in 0.8 s, which is the FTS-reindex bug's own proof. The export streamed a **134 MB payload while RSS rose 52 MB** (buffered would need 134 MB+). Client-side, **opening the library costs the same at 2,000 entries as at 500** — 60 cards, 1,619 nodes, ~24 ms, against the 2,295 ms / 10,851 nodes on record. One limit remains and is **deliberate, not a bug**: the windowed render appends without evicting, so scrolling to the end accumulates DOM for the session (501 cards / 13,480 nodes at 500 entries; ~135k nodes extrapolated to a fully-scrolled 5,000). It costs ~4% on a re-render (330 ms collapsed vs 343 ms expanded, debounce-dominated) and self-heals — any filter drops back to a 120-card, 3,233-node window. Worth revisiting only if libraries reach thousands *and* users scroll them end to end; the fix would be virtual scrolling, which needs fixed row heights the card grid does not have.
- **`GET /api/saved` pages only when asked.** Bare `/api/saved` returns the whole metadata array exactly as it always did (the export, the vault sync and the plugin all want that); `?limit=&offset=` returns `{entries, total, hasMore}`. - **The digest streams, and every layer of that has a fallback to the way it worked before.** `POST /api/digest?stream=1` opens an SSE response with four event types: `phase` (map-reduce progress, before any digest text exists), `token`, `done` (the *identical* payload the JSON route returns), and `error`. **Without `?stream=1` the route still answers with plain JSON** — the Obsidian plugin and anything else built against it must not start receiving an event stream. - **The extension fetches transcripts and hands them over in the URL fragment.** It scrapes on the visitor's own tab (their IP, their session) and passes the payload as `#echo-tx=<gzip+base64url>`. No new server route and no new permission were needed: `/api/digest` already takes the transcript text from the client, and a fragment is never sent to the server. Four traps worth recording: **(1) `src/client/main.js`'s validator is the real trust boundary**, not the extension's copy — any page can send a visitor to `<echo>/?v=ID#echo-tx=<payload>`, so the fragment is attacker-reachable and is re-validated from scratch. **(2) The DECOMPRESSED size is bounded separately** from the 1.5 MB encoded cap — gzip reaches ~1000:1, so the encoded cap alone would permit a >1 GB …
- **`npm run serve:public` — the working answer to datacenter IP blocking.** `tools/holesail-serve.mjs` starts Echo and opens a Holesail P2P tunnel, fronted by a Janus gateway, printing a stable public `https://0000<key>.janus.ssani.dev/` URL. Because Echo then runs on a residential IP, transcripts work. Verified end to end 2026-07-26: Janus returned Echo's page over HTTPS (200), and the exact video that failed on the VPS with `reason=bot_block` returned 1077 caption segments through the tunnel. Sharp edges: the seed at `.holesail-seed` is persisted so the URL is STABLE across runs (a fresh key each launch would mean a fresh URL), it is the serving capability so it is mode 0600 and gitignored; `secure:false` is required because Holesail's secure mode returns the seed AS the key and Janus rejects that form on purpose; `needsSecurityBanner()` fails SAFE, warning unless the mode is exactly 'web', because server.js resolves ECHO_MODE by exact match and falls back to local, so an unrecognised value is precisely one that IS exposing the library; it lives in `tools/` to stay out of server.js's import graph (which `tests/tauri-bundle.test.js` walks); and it is a devDependency so `pkg:stage-deps` (--omit=dev) keeps it out of the desktop bundle. Exposing local mode publicly means anyone with the link can spend the Claude CLI quota and read/write the library — mitigate with a Janus per-key password or run with `ECHO_MODE=web`. Use `npm run serve:public -- --help` to see all flags.
- **CSS media query range syntax is an Astro + bundler footgun.** Left at its default `vite.build.cssTarget`, the CSS minifier rewrites every `(max-width: 520px)` into the Media Queries Level 4 range form `(width <= 520px)` — semantically identical, but unsupported by Safari below 16.4. A hand-written stylesheet that worked everywhere silently stops applying its breakpoints on older browsers, with no error and no indication anything is wrong. `vite.build.cssTarget` is pinned in `astro.config.mjs` to `['chrome87','firefox78','safari14','edge88']` to prevent it. The benign half of the same pass — merging two rules that share a declaration block into one comma-separated selector — is left enabled.

- **A response that stops at the output ceiling is not an error the API reports — it has to be read.** `ApiKeyProvider` hardcoded `max_tokens: 16000` and **`stop_reason` was read NOWHERE in this repo**, so a digest cut off at the ceiling came back as an ordinary success: saved to the library, exported to Markdown, written into the vault, mirrored to the PDS, indistinguishable from a complete one. In `article` mode 16k output tokens is roughly 90 minutes of video, so it truncated on any long video — and only on the BYOK path, the one path already listed as unverified. Now `isTruncationReason()` (`providers.js`) reads both spellings (`stop_reason: 'max_tokens'`, `finish_reason: 'length'`) plus the CLI's own field defensively; `generateDigest()` propagates `truncated` out of the fast path **and out of both map-reduce phases** (a truncated *map* chunk is a hole in the middle, which nothing else would reveal); and the client shows `#digestTruncationNote` **next to the text it applies to** rather than as an error card, because the text that arrived is real and was already on screen when it streamed. Ceilings now come from the registry per provider, so a new provider cannot inherit `16 000`: **wire its finish reason into `isTruncationReason()` or its ceilings will be invisible.** DeepSeek's is 384 000 and it is *sent*, not omitted — leaving `max_tokens` unset hands the choice to the API's **default**, which is far below the model's maximum and truncated an article at 6 552 words in the first A/B run (fixed: 9 030 words, 27/27 numbers, 96% coverage).
- **Reasoning is a variable, so it is a control — and it must never reach the digest.** Anthropic always sent `thinking: {type:'disabled'}` while DeepSeek sent nothing at all, so switching provider changed the model AND the reasoning mode at once and any difference in the output was unattributable. `reasoningFields()` gives both one vocabulary (`off`/`low`/`medium`/`high`) expressed in each provider's own dialect — a token budget **clamped below `max_tokens`** on Anthropic (out of range is a hard 400), `reasoning_effort` on DeepSeek, and **nothing at all for the CLI**, so that path stays byte-identical. Off is the default and is SENT rather than omitted, otherwise each API's own default decides. **The dialect is passed by the caller, never inferred from `opts`**: the DeepSeek provider is reached with a bare `{ apiKey }`, and a bare key means *anthropic* to `getProviderId()`, so inferring it sent `budget_tokens` to an API expecting `reasoning_effort` — found by asserting the **request body** rather than the resolver's return value. Reasoning output is filtered on every transport path (`thinking` blocks, `reasoning_content`, `delta.reasoning_content`): a model's deliberation is not part of the answer and would otherwise land in the library, the export and the PDS.
- **A key test that names one provider is a bug, and the async provider list makes it worse.** Five client call sites asked `getApiKey()` — Anthropic's storage slot — when the question was "does this user have a key?", so in web mode a visitor who chose DeepSeek got **no auto-digest at all**: no error, nothing logged, nothing on screen. They now call `activeApiKey()`, which asks the SELECTED provider. That fix then exposed the race underneath: `activeApiKey()` resolves through `activeProviderId()`, which validated the stored preference against `PROVIDER_LIST` — a list that arrives from `GET /api/providers` **asynchronously**, while `autoLoadFromQuery()` applies an extension transcript **synchronously** during INITIALISE. On a cold load the transcript landed first, `activeProviderId()` returned `''`, and the first AI request went out with **no `X-Echo-Provider` header** — a DeepSeek key sent to Anthropic. A stored preference is now trusted on its own; the list only says which preferences exist. `tests/providers.test.js` guards **both** shapes (a call to a provider-specific accessor, and a string literal passed to `getKeyForProvider()`), because the first version of that guard checked only the former and a mutation reintroducing the identical bug as `getKeyForProvider('anthropic')` passed it.
